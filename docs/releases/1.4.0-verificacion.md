## Preparación

Los cinco archivos y las raíces de ambos lockfiles coinciden en 1.4.0.
`check.cjs v1.4.0` y `checkDraft` pasan sin crear etiquetas. El manifiesto está
desactivado (`enabled:false`), con `publishedAt:null`, enlace previsto y ocho
notas idénticas a `1.4.0.md`. El generador y el workflow reutilizarán ese mismo
Markdown como cuerpo del borrador y como notas de la app.

Se contrastaron las notas con los cambios desde `v1.3.46`: Chat (PR #5), Repaso
(#11), catálogo R1 (#7), Office (#8), horario (#9), aviso (#3), retirada de
tarjetas de Configuración (#4). DOCX y plantillas pertenecían a la versión de
origen y no se anuncian como novedades. Se agrupan Office/horario en un punto
para respetar el límite de ocho notas compartidas, conservando ambos arreglos.

No cambia código funcional, dependencias ni migraciones. Un test del actualizador
necesitó fijar explícitamente su versión de origen 1.3.46: antes asumía que
coincidía con el package actual y fallaba al subir este a 1.4.0. Solo cambia el
fixture del test, no el comparador ni la aplicación.

## Comprobado de verdad, en aislamiento de perfil

Antes de ejecutar el código principal, el depurador fija `userData` y
`sessionData` a un perfil de pruebas dedicado. El caché del actualizador también
se redirige a una carpeta dedicada. Las ventanas permanecen ocultas, la app carga
solo una página local de ensayo y se desactiva la instalación automática.
No se cambia ningún archivo del código empaquetado ni de la instalación personal.

El proveedor de actualizaciones del ensayo es un servidor local, no GitHub:

- Ejecutable 1.3.46 con manifiesto 1.3.46: evento nativo `current`, no ofrece actualizar.
- Ejecutable 1.3.46 con manifiesto 1.4.0: `available`; descarga completa real del EXE.
  El actualizador verifica su hash y el ensayo contrasta además SHA-256.
- Ejecutable 1.4.0 con manifiesto 1.3.46: `current`, no ofrece bajar de versión.
- Ejecutable 1.4.0 con manifiesto 1.4.0: `current`, no ofrece reinstalarla.

Se guardan datos sintéticos en localStorage y en las instancias IndexedDB de
Biblioteca (`academic-autopilot/library_books` y `library_files`) usando
localforage. Tras cerrar 1.3.46 y abrir 1.4.0 sobre el mismo perfil aislado,
el texto local, metadatos del libro, notas y marcadores coinciden exactamente.
El PDF conserva SHA-256 `15554281f787be16b5482e0472ea28edbb9c9e7e8ff35f00214f2a440cb3a59e`.
Es un PDF válido de una página, comprobado con pypdf; el hash de ambos perfiles
coincide también con el del archivo de prueba. El primer instrumento guardaba
solo un bloque con cabecera PDF; se corrigió y se repitió todo el ensayo nativo
con el PDF válido antes de aceptar este resultado. No son datos personales.

**Esto es un ensayo parcial de transporte nativo y conservación del perfil al
cambiar de ejecutable; NO acredita la instalación/actualización NSIS completa.**
No se probó el reinicio a través del instalador, SmartScreen, descarga diferencial,
interrupción de descarga ni apertura del PDF desde el lector en Electron.
El smoke web prueba por separado la importación/lectura de PDF local.

No hay Windows Sandbox disponible ni VM Windows instalada lista para usar.
La VM de VirtualBox existente tiene un disco prácticamente vacío y no se tocó.
Ejecutar NSIS con el mismo GUID en el host puede afectar registro/accesos del
usuario incluso eligiendo otra carpeta: queda pendiente un Windows invitado
de pruebas, sin servicios de pago. Mac no se construyó ni probó aquí.
